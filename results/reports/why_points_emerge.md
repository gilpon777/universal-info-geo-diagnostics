# 検証: コードを走らせると、なぜ「注目点」が出てくるのか

作成: 2026-11-09
問い（中谷）: コードに不備が無いことは検証されているはず。では、なぜ走らせると注目点が出てくるのか。

## 0. 前提の再確認（コードの検証範囲）

本日 `test_v2.py` を再実行し、全テスト通過を再確認した。検証済みの範囲は数値の正しさである:

- 線形モデルで解析解 AᵀΣ⁻¹A と相対誤差 2.3×10⁻¹⁰ で一致（ヤコビアンと FIM 組み立ての正しさ）
- パラメータの単位を 10⁶ 倍しても Scaled 指標は相対変化 1.3×10⁻¹¹ で不変（スケーリング処理の正しさ）
- 既知の sloppy モデルで、固有値スペクトルと実効ランクが理論通り（スペクトル指標の正しさ）
- 本検証でも、保存済み J と共分散から貪欲選定を再実行し、`summary.json` の順序
  [0, 5, 9, 2, 7, 11, 6, …] を完全再現した（決定性と再現性）

つまり注目点はバグや乱数の産物ではない。以下は「正しく計算された結果として、
なぜ特定の点が浮かび上がるのか」の機構分解である。

## 1. 第1位の機構: 注目点 =「勾配 ÷ ノイズ」が最大の点

貪欲選定の最初の1点は、logdet の単調性から、実質的に
**白化勾配ノルム ‖J_i‖²/σ_i² が最大のビン**である（順位はこのスコアと一致）。
ボイドの中心ビン（r = 0.07 Rv）の内訳:

| 量 | 中心ビン | 他ビンとの比較 |
|---|---|---|
| 勾配ノルム ‖J‖ | 0.99 | 中央値 1.37、最大は壁内側の 3.3。**中心は勾配では勝っていない** |
| ∂プロファイル/∂δc | 0.99 | 中心ではプロファイル ≈ 1+δc そのもの。δc の直接の読み出し口 |
| ノイズ σ（ブートストラップ） | 0.0029 | 中央値 0.028 の **約1/10** |
| スコア ‖J‖²/σ² | 118,220 | 2位（0.79 Rv）の 8,322 に対して **14.2倍** |

勝因の分解: 勾配の寄与はむしろ負（(0.99/3.3)² ≈ 0.09）で、
ノイズの寄与が (0.034/0.0029)² ≈ 140 倍。**中心が1位なのは「感度が大きいから」ではなく
「ノイズが桁違いに小さいから」**である。中心密度は全ボイドで平均の 0.7% とほぼゼロに張り付き、
密度がゼロ未満にならない下限の効果もあって、ボイド間のばらつきが圧縮されている。
そこに δc が係数ほぼ1で直接効くため、「δc を ±0.003 で読める観測点」として浮上する。

言い換えると、コードが出す注目点とは「情報 = 勾配²/ノイズ が最大の場所」であり、
それは直感の「物がたくさんある場所」ではなく「静かで、かつパラメータが直接読める場所」になりうる。
中心の例はその典型である。

## 2. 2位以降の機構: 「まだ縛れていない方向」を埋めにいく

2点目以降の logdet 増分は、既選の集合でまだ拘束されていない方向（sloppy 方向）に
候補の勾配がどれだけ成分を持ち、かつノイズに対して大きいかで決まる:

- 中心を選んだ直後の sloppy 方向は α・rs の混合（固有ベクトル [0.01, −0.45, 0.89, 0]）。
  2位は 0.79 Rv（rs への勾配 −3.1 と最大級）だった。
- 3点目の時点では sloppy 方向はほぼ純粋な β（[0, 0, 0, −1.0]）になり、
  3位は β への勾配を持つ外側の 1.36 Rv だった。

そして増分は急速に枯れる: logdet の増分は4点目までで全体の 97%、
7点目以降の増分は 0.1 以下（最終的には 0.005）。**注目点が「少数だけ」出てくるのは、
有効な方向の数が有限で、埋まったら増分がゼロになるから**である。
順位表の長さではなく、この飽和曲線が情報構造の姿である。

## 3. アブレーション: 何が順位を決めているか

| 改変 | 結果（上位7） | 読み |
|---|---|---|
| 等ノイズ化（σ を全ビン共通に） | 1位が 0.93 Rv（勾配最大）へ交代、中心は2位 | 中心1位はノイズ構造が主因、と確定 |
| 共分散を対角のみに | [0,5,9,2,11,6,3]、上位集合は不変 | ビン間相関は脇役 |
| ビンの入力順をシャッフル | 同じ物理的ビンの集合を復元 | 実装の健全性（順序依存バグなし） |
| ノイズ全体を100倍 | 順序は完全不変 | 注目点は相対 S/N 構造で決まる |
| 中心ビンを除外 | 次点の 0.79 Rv から階層が続く | 階層はデータ駆動で、中心はその頂点 |
| θ を δc=−0.90 に摂動 | 上位7は不変 | 中心近傍では頑健 |
| θ を β=3.0 に摂動 | 順位が大きく変動（13 が2位に） | 注目点はフィット点局所の量であり、普遍定数ではない |

## 4. ヌルテスト: コードは「無いところに点を作る」か

正直な検査として2つ:

- **勾配が全部同一の世界**（方向の多様性を消したヌル）: 1点目の後の logdet 利得は
  合計 0.40（実データ 56.5）。2点目以降は増分がほぼゼロで、順位は無意味な並びになる。
  **方向の多様性がなければ、コードは意味のある注目点を作れない。**
- **ランダムなヤコビアン**: それでも順位表は出てくる（argmax は常に存在する）。
  利得総量は実データと同程度にもなりうる。つまり「順位表が出る」こと自体は発見ではない。
  データ固有の意味は、(a) どの点が選ばれるか、(b) 1位のマージン（実データで14倍）、
  (c) アブレーションへの安定性、に宿る。ボイドの中心については (a)(b)(c) が揃っている。

対照として天の川: スコア1位は貪欲1位の 18.2 kpc と一致するが、
2位とのマージンは **1.005倍** のほぼ同点である。同じコードでも、
注目点の「鋭さ」は対象ごとにまったく違う。コードが機械的に鋭い点を
作っているのではないことの、もう一つの証拠である。

## 5. 結論

注目点が出てくる理由は3つの掛け算である:

1. **読み出し口**: その点の観測量が、どれかのパラメータをほぼ直接読む形になっている
   （中心密度 ≈ 1+δc）。
2. **静けさ**: その点のノイズが小さい（中心は密度の下限に張り付き、ばらつきが圧縮される）。
3. **未開拓の方向**: 既に選んだ点が縛っていない方向に勾配が向いている（2位以降）。

コードの仕事は、この積を全候補について正確に評価し、logdet 増分として
順位化することであり、その数値の正しさは解析解との一致で検証されている。
同時に、注目点は (J, 共分散, フィット点, パラメータ化) の関数であり、
β を動かせば順位が変わること、等ノイズ化すれば1位が交代することからも分かる通り、
「宇宙に刻まれた絶対の点」ではなく「この観測とモデルの組み合わせにおける情報の地形」
である。地形が実在することは、飽和曲線とアブレーションの安定性が示している。
