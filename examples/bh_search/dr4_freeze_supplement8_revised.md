## 第1部: 改訂項目（第6回査読の検証で確定した変更）

### 1. 減光規約の文言（a0 は A_G ではない）

- TGE の `a0` は、Gaia DR3 公式ドキュメント（Doc 1.3、§11.3.11 および §20.2.3）によれば Fitzpatrick (1999) 減光則のパラメータ A_0、すなわち**波長 541.4 nm の単色減光**のピクセル内トレーサー中央値である。A_G はスペクトル依存のバンド積算量であり、a0 を A_G や A_V と同一視する公式の根拠はない。
- したがって現行規約の文言を改める: A_G,max の TGE 分は「A_V 天井そのもの」ではなく、**「A_0 ベースの保守的な天井の代理量」**と明記する。
- 変換の不確かさへの感度は確認済みである: A_G,max(k) = max(GSP-Phot, k·a0)、k = 0.8–1.1 の全範囲、および天井をピクセルの a0_max に置く最悪ケースでも、**全13件のラベルは不変**（非支持4件は余裕 ≥ 1.5 を維持）。Delchambre et al. 2023 では巨星で A_V/A_0 ≈ 0.98 であり、この代理の緩さは主に A_G < A_V の側、すなわち余裕を小さく見積もる保守側に出る。
- 根拠: `extinction_anchor_check.md` / `.json`（TGE の a0_min / a0_max / a0_uncertainty / num_tracers_used / status も取得・記録済み。全ピクセル status=0 (Nominal)）。

### 2. アンカー M_G(3 M☉) の正本の切替

- 3 M☉ 主系列星の絶対等級の正本を、Pecaut & Mamajek の EEM 原表（Version 2022.04.16）から対数補間で得られる **+0.30** に切り替える（B8V: 3.38 M☉, M_G = −0.01／B9V: 2.75 M☉, M_G = 0.515 → 3.0 M☉ で +0.29〜+0.30）。
- 従来の **−0.1 は出典を辿れず**（dr4_beta_scan2.py 由来）、scan3 アンカー表内部の隣接点からの補間値（−0.23）とも不整合だったため、感度側へ降格する。旧アンカーは 2.2–5.5 M☉ の全域で EEM 2022 より 0.38–0.58 等明るい系統差があり、β走査の高質量側にも効く点として記録する。
- アンカー切替による**ラベルの変更はない**（第1項の感度グリッド内で確認済み）。
- 根拠: `extinction_anchor_check.md` §3。

### 3. 閾値 1.5 等の位置づけ

- 非支持の光度条件「余裕_非支持 ≥ 1.5 等」は、**物理的に確立された境界ではなく、暫定的な運用基準**と明記する（内訳はアンカー誤差 ±0.5 等の見積もりと、回転・金属量・未分解連星への追加余裕 1.0 等で、後者にはまだ十分な定量的裏付けがない）。
- この位置づけの明記のうえで、運用基準として維持する。

### 4. 「BH非支持」の適用範囲（階層三重系の限定）

- 「BH非支持」は、**単一伴星モデル（暗い伴星、または単一の主系列伴星）の下での判定**であり、階層三重系（明るい星＋暗い重い天体の内側連星）までは排除していないことを、ラベルの定義として明記する。
- 根拠: Claude v8 の反例提示と Muse の検証。スポット解2件について Mardling & Aarseth (2001) の安定条件（共面・順行形）で内側軌道の窓を計算した結果、#4 は内側周期上限 約76日、#9 は上限 約1.3日（e_out = 0.94 のため狭い）と、**安定窓のある解が両系に存在し、反例は力学的安定性の観点では現時点では棄却できない**（`triple_stability_check.md`）。ただし安定窓の存在は三重系の存在証明ではなく、発生確率には触れていない。Kozai–Lidov による離心率励起は未評価。
- なお Claude の全探索（解数を含む）の独立再現は未了であり、Claude には全探索コードと全解一覧のアップロードを依頼済みである。

### 5. 参照実装の正本

- DR4 判定の参照実装は、フェイルセーフ版 **`dr4_apply_rules_v2.py`** を正とする。
- v1 には「データ不足を問題なしと誤認する」暗黙の初期値が5件（対応付け欠落→対応A、軌道解フラグ欠落→解あり、色欠落→旗なし、解の種類欠落→astrometric 等）と例外で落ちる経路が4件あり、特に v1 のテストベクトル全13件が「対応付け欠落→対応A」の暗黙初期値に依存していた。v2 は入力不足の天体を自動的に「判定保留（入力不足）」へ倒し（理由に不足項目を明記）、完全な入力では v1 と全25ケース完全一致（status: OK）する。
- 根拠: `failsafe_check.md`、`dr4_apply_rules_v2.py`。

## 第2部: Muse の提案（検証済み・考察つき）

### 提案1: DR4 当日のドライラン結果と当日の運用

**検証結果**（`dr4_dryrun.md`、`dr4_dryrun.py`）:
- 6シナリオ・**117件の判定が全て例外なく完走**した（総実行時間 0.013 秒）。
- S0（基準・回帰）: 13件すべてが評価表 v4 の最終ラベルと一致。
- S1（f 区間の対数幅を半減）: **ラベル変化ゼロ**。#12 は M2 上限が 92.2 → 17.23 と有限化するが、それでも 3 M☉ をまたぎ保留のまま。
- S2（BH1 の f 区間を確定側に置換）: BH1 は BH候補のまま確定。
- S3（軌道解の喪失と出現）: 解を落とした天体は「軌道解なし」へ、仮の解を与えた天体は判定が回り、正しく追随した。
- S4（入力欠損の混入）: 欠損は全て「判定保留（入力不足）」に倒れ、理由が明示された。
- S5（境界ケース）: M2 上限が 3 M☉ をまたぐ形では保留側に倒れた。

**考察**:
現在の保留4件は、f の精度では解けない。#13 の保留理由は光度天井の余裕 −0.14 等（f に依存しない）、#8 は主星の主系列前提の弱さ、#10 は SB1 の傾斜角による原理的な上限なし、#12 は区間を半減しても上限が 3 M☉ を割り込まない。つまり **DR4 の「精度向上」だけでは決着せず、決着に要るのは精度ではなく新しい種類のデータ**（DR4 の RVS エポック視線速度、進化星モデル C/D）である。当日の律速は判定計算（0.013 秒）ではなく、入力の組み立てと判断にある。特に解の種類の分類（DR4 で新種の解が出た場合の扱い）は基準側の未決事項として残る。

**提案**:
ドライランを固定前の最終確認として追記8に組み込み、当日の手作業チェックリスト（`dr4_dryrun.md` の9項目: 解の有無と solution 分類、f 区間の再計算、M1 範囲の再構築、M_G / M_G_corr / dcolour の算出、対応付け判定、f95_frozen の入力操作、MSC ブラケット照合、軸・理由・余裕まで含めた記録、パイプライン外の留保事項の判断）を統合規則文書の付録として付ける。解の種類の分類規則（加速度解・AstroSpectroSB1 等への対応）は DR4 前に三者で決める。

### 提案2: GW S フィットの参照規約

**検証結果**（`gw_sfit_reference.md`、係数表 `gw_sfit_coefficients.json`）:
- 全19点×2窓の係数表（b, q, a, cosθ 相当量、残差）を固定し、**同一の係数表から** ChatGPT の OLS 傾き（計画窓 0.864／信号整合窓 0.759）と Claude の TLS 傾き（0.999／1.007）の**両方が再現**した。
- q < 0 で a = √q が定義できない点が6件あり、有意点である (400, 1.0) 信号整合窓（q = −3.174×10⁻⁴）も含む。q の符号はフィット方法に依らない。

**考察**:
p 論争は算術の対立ではなく、**方法の未明記**が原因だった。(400, 1.0) が「有意なのに q が負」なのは、その応答が g² 項（パワー的な応答）ではなく g の交差項で立っている、すなわち**干渉的な応答**であることを示す。また Claude の cosθ 要約統計が再現しない一因は点集合の数え方にある可能性がある: a が定義できない点を落とすと信号整合窓の傾きの点集合は n=11 ではなく n=10 になる。なおベクトル解釈（cosθ・実効次元 D）は、係数から cosθ = +5.03 のような真の余弦ではあり得ない値が出ること自体が反証であり、経験的応答モデルへの格下げが妥当である。一方、実測 g99 の回帰は Claude v7 の傾き（−0.91／−1.07）を正確に再現しており、osc_proj の物差し自体は維持される。

**提案**:
傾き p は **OLS と TLS を方法名つきで併記する規約**を三者の標準とする（「p = 1.00 ± 0.20」のような方法名なしの確定値としては扱わない）。Claude には、フィットコード公開時に点集合の定義（n の数え方）と ±0.20 の出所の確認を求める。

### 提案3: κ 指紋の部分実施

**検証結果**（`kappa_fingerprint_partial.md`）:
- 全441同時注入の実測応答と K·t 予測の残差 r は、**最大 0.041σ・RMS 0.0047σ**。
- 符号つき残差は θ・近傍数と実質無相関で、符号の偏りもない（正235／負206）。
- 一方で |r| は小さい θ に集中する（Spearman −0.571、|r| 上位10件は全て θ ≤ 4.5°・高 z 側）。
- 指紋 F1–F6（回収率、最大絶対残差、RMS 等の分布統計、Pearson 相関、相関構造、符号の偏りと帯域別内訳）を実測値で固定した。

**考察**:
|r| の小 θ 集中は、既知の対角誤差 E1 の ∝1/θ 傾向と方向が一致する。つまり指紋の残差はランダムな数値ノイズではなく、**半解析近似の効きが弱い領域（小さく見える遠方ボイド）を正しく指している**。したがって独立実装との照合は全域一括ではなく θ 帯域別に見るべきである。ただしこの指紋は同一パイプライン系統内の自己整合（重ね合わせの線形性と数値実装の整合）の固定であり、演算子そのものの独立な正しさの証明にはならない。その部分は第2実装（ChatGPT の独立実装）待ちである。

**提案**:
指紋方式を K 仕様書 v1.2 に取り込む際、F1–F6 の実測値を基準値として登録し、独立実装との照合条件は **θ 帯域別**に置く。あわせて、対角分の行和伝播 δc は最大 0.0014σ（包絡 0.0048σ）で要素基準より小さいことを既報の値として併記し、非対角分は独立実装の到着後に評価する。
