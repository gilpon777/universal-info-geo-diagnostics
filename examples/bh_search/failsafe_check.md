# 参照実装 dr4_apply_rules.py のフェイルセーフ化（v2）と検証結果

作成: 2026-11-17（Muse）/ 対象: `dr4_apply_rules.py`（v1、Claude 作成）→ `dr4_apply_rules_v2.py`（新規）
発端: ChatGPT の指摘 — 現行コードには「データ不足を問題なしと誤認する」初期値がある。
方針: v1 は無改変。v2 は新規ファイル。完全な入力がある場合の判定ロジックと出力形式は v1 と同一に保ち、欠落・形式異常の経路だけをフェイルセーフ側（判定保留（入力不足）／判定不能）に倒した。

## 1. 洗い出した初期値・欠損処理の一覧（v1）

| # | 箇所（v1） | v1 の挙動 | 種別 |
|---|---|---|---|
| 1 | `o.get("match","A")` | 対応付けが無い → 対応 A とみなして判定を進める | 問題なし側の初期値 |
| 2 | `build()` が match を設定しない | テストベクトルの 13 件全てが #1 の初期値に依存していた（暗黙に全件 A 扱い） | 問題なし側の初期値 |
| 3 | `o.get("has_orbit", True)` | 軌道解の有無が未指定 → 「あり」とみなす | 問題なし側の初期値 |
| 4 | `colour_flag(...) if "dcolour" in o else "なし"` | 色データが無い → 「色の旗なし」 | 問題なし側の初期値 |
| 5 | `o.get("solution","astrometric")` | 解の種類が未指定 → astrometric（= SB1 ではない）とみなす | 問題なし側の初期値 |
| 6 | `max(ag)`（ag は GSP・TGE の非 None のみ） | 減光が双方とも無い → `ValueError: max() iterable argument is empty` で例外終了 | 例外で落ちる |
| 7 | `o["M_G"]` / `o["M_G_corr"]` / `o["M1_range"]` の直接参照 | キー欠落 → KeyError で例外終了 | 例外で落ちる |

注記（#10 について）: f95_frozen は「凍結区間が登録されている場合にだけ照合する」任意入力であり、13 件の入力には元々含まれない（照合は合成ベクトル S11 でのみ使う）。必須化すると回帰確認（§3）が成立しなくなるため、v2 でも任意入力のままとした。ただし「欠落 = 照合しない」ことは v2 の docstring と本書に明示した。

## 2. v2 の変更点

- `label()` の前段に必須入力チェックを追加した。欠落があれば、その天体は **「判定保留（入力不足）」**（質量軸・測光軸は「判定不能」）となり、理由に不足項目を列挙する。チェック順は v1 の分岐順に合わせた:
  1. match（欠落 → 入力不足 / "D" → 対応不明［v1 と同一］）
  2. has_orbit（欠落 → 入力不足 / False → 軌道解なし［v1 と同一］）
  3. 軌道解がある場合の必須入力: f95、M1_range、M_G、M_G_corr、solution、dcolour、減光（GSP・TGE の少なくとも一方）
- 本体の判定は `_label_core()` として v1 のロジックをそのまま移した（初期値つきの `.get()` は、存在が保証された直接参照に置き換えただけ）。想定外の形式の入力で計算が例外になった場合は、最後の受け皿で **「判定不能」**（理由に例外の内容を記録）に倒し、例外で落ちる経路を無くした。
- `build()` では match="A" を入力として明示した（13 天体は評価表 v4 の source_id で同定済みであり、対応 A が事実。値そのものは v1 の暗黙の初期値と同じで、判定は変わらない）。
- 出力 JSON のファイル名のみ `dr4_test_vectors_v2.json` に変えた（v1 の出力を上書きしないため）。出力の形式・内容は同一。

## 3. 回帰確認の結果

方法: v1・v2 を /tmp の作業コピーでそれぞれ実行し、標準出力と JSON 出力（実 13 件＋合成 12 件の output 全体: label / mass_axis / phot_axis / reasons / margins）を機械比較した。

- v1: status: OK（終了コード 0）
- v2: status: OK（終了コード 0）
- 標準出力は完全一致。JSON の output は実 13 件・合成 12 件の全件で完全一致（入力側の唯一の差は v2 の build が match="A" を明示する点のみ）。
- 評価表 v4 の最終ラベルとも全 13 件で一致: #1・#2・#3・#5・#11 軌道解なし / #4・#7・#9 BH非支持 / #6 BH候補 / #8・#10・#12・#13 判定保留。

## 4. 欠損テストの結果

13 件の入力から項目を 1 つずつ欠落させ、v1 と v2 の挙動を比較した（v2 は全ケースで例外なくフェイルセーフ側に倒れた）。

| テスト | v1 の挙動 | v2 の挙動 |
|---|---|---|
| T1 #6 dcolour キー削除 | BH候補（旗「なし」として処理） | 判定保留（入力不足）: 色の差（dcolour） |
| T2 #6 dcolour=None | 例外 TypeError（abs(None)） | 判定保留（入力不足）: 色の差（dcolour） |
| T3 #6 減光の双方 None | 例外 ValueError（max() が空） | 判定保留（入力不足）: 減光（双方） |
| T4 #6 減光 GSP のみ None（対照） | BH候補 | BH候補（不変。一方があれば足りる — 実データの #1・#8・#10 がこの形） |
| T5 #4 match キー削除 | BH非支持（A とみなして処理） | 判定保留（入力不足）: 対応付け（match） |
| T6 #4 has_orbit キー削除 | BH非支持（「あり」とみなして処理） | 判定保留（入力不足）: 軌道解の有無（has_orbit） |
| T7 #9 solution キー削除 | BH非支持（astrometric とみなして処理） | 判定保留（入力不足）: 軌道解の種類（solution） |

## 5. まとめ

- ChatGPT が挙げた 4 件（色・対応付け・軌道解フラグ・減光の max([])）に加え、solution の初期値、M_G / M_G_corr / M1_range / f95 の欠落時の例外経路も同種の問題として洗い出し、全て v2 でフェイルセーフ側に倒した。
- 完全な入力では v1 と出力が完全一致することを機械比較で確認済み。v1 ファイルは無改変。
