# 減光の扱いと光度天井アンカーの検証

作成: 2026-11-17（Muse）/ 対象: ChatGPT 第5回査読「優先1: Gaia の減光と光度天井」への回答材料。
数値の基: `dr4_rule_check_v2.json`（M_G）、`gaia_extinction_13.json`（GSP-Phot A_G / TGE a0）、`dr4_beta_scan3.py`（アンカー表）。
詳細数値は `extinction_anchor_check.json` に全件収録。既存ファイルは変更していない。

## 結論の要約

1. **ChatGPT の指摘は正しい**: TGE の `a0` は A_G でも A_V でもなく、波長 541.4 nm の単色減光パラメータ A_0。現行規約の「a0 を A_V 天井として流用」は近似であり、厳密な上限としての根拠は公式ドキュメントに無い（§1）。
2. **ただし感度を取ると結論は動かない**: 変換係数 k = 0.8–1.1 とアンカー −0.1 / +0.30 の全グリッドで、判定に関わる全天体のラベルは不変（§2）。最も厳しい補助ケース（天井 = ピクセルの a0_max）でも不変。
3. **アンカー +0.30 は正しい**: Pecaut & Mamajek の EEM 原表（2022.04.16 版）で自力補間すると +0.29（ChatGPT の引用値では +0.30）。現行 −0.1 は出典を辿れず、scan3 アンカー表内部とも整合しない。正本を +0.30 に切り替えることを推奨（§3）。

## 検証1: TGE a0 の定義と追加項目

### 定義（Gaia DR3 公式ドキュメントより）

- `a0` は、ピクセル内の減光トレーサー（巨星）の **A_0 の中央値**。A_0 は採用減光則（Fitzpatrick 1999）のパラメータで、**波長 541.4 nm における単色減光**として定義される。トレーサー個々の値は GSP-Phot の `azero_gspphot`。
  （Gaia DR3 Documentation 1.3, §11.3.11 および §20.2.3 の列定義）
- バンド減光（A_G 等）は A_0 から別途変換して得るもので、スペクトル依存（同ドキュメント §11.2.3 の手続き）。**a0 をそのまま A_G や A_V と同一視する記述は公式ドキュメントに無い。**
- `a0_uncertainty` は「平均値の不確かさ」、すなわちトレーサー平均の標準誤差であり、**星ごとのばらつきではない**。対象ピクセルでは 0.009–0.012 等。
- `a0_min` / `a0_max` はピクセル内トレーサーの最小・最大で、対象ピクセルでは幅 1.17–1.55 等。**視線ごとのばらつきは a0_uncertainty より2桁大きい。** TGE は当該星の減光の直接測定ではなく、HEALPix level 6（約 0.84 deg²）ピクセルの代表値である。
- 補足: Delchambre et al. (2023, Apsis III) によれば巨星（3000 < T_eff < 5700 K）では **A_V/A_0 ≒ 0.98**。つまり a0 は A_V より僅かに大きい側にあり、「a0 を A_V 天井とする」ステップ自体は保守的。近似の緩さは主に A_G < A_V の側（k < 1）に出る — それを検証2で扱った。

## 検証2: 変換係数 k の感度

A_G(天井) = k × a0 と置き、A_G,max(k) = max(GSP-Phot A_G, k·a0)、余裕 = (M_G − A_G,max(k)) − M_G(3 M☉) を再計算した。閾値は光度天井条件の 1.5 等。

- **支配関係**: k = 0.8–1.1 の全域で、#12 を除く12天体は TGE 側が A_G,max を支配する。#12 は全域で GSP-Phot（2.6713）が支配し、k に依らない。

- **判定: ラベル変更なし。** 非支持の4件（#4・#7・#8・#9）は全グリッドで余裕 ≥ 1.5 を維持（最小は #4 の +2.23）。#13 は全グリッドで 1.5 に届かない（最大 +0.05 は k=0.8・アンカー −0.1 のセルで、符号は正転するが閾値には遠い）。#12 は質量軸で保留が決まっており不変。
- 注記: #5 はグリッド内で「余裕 ≥ 1.5」の真偽が反転するが、#5 は軌道解なし（質量軸の対象外）で天井条件を適用しないため、ラベルへの影響はない。
- **補助感度（天井 = a0_max）**: ピクセル代表値ではなくトレーサー最大値を天井に置く最も厳しいケースでも、#4 +1.62（アンカー +0.30）/ +2.02（−0.1）、#9 +1.75 / +2.15 と閾値を維持し、#13 は −1.24 / −0.84 と負のまま。ラベル不変。

## 検証3: M_G(3 M☉) アンカーの出典

### EEM 原表での補間（Pecaut & Mamajek 2013 の EEM dwarf table、Version 2022.04.16、pas.rochester.edu、2026-11-17 閲覧）

| 型 | M (M☉) | M_V | M_G |
|---|---|---|---|
| B8V | 3.38 | 0.00 | −0.01 |
| B9V | 2.75 | 0.50 | 0.515 |
| B9.5V | 2.68 | 0.60 | 0.615 |

質量の対数で線形補間（β走査のコードと同じ方式）すると:

- B9V–B8V 間（原表の実値 M_G = 0.515 / −0.01）: **M_G(3.0 M☉) = +0.29**
- ChatGPT の引用値（B8V の M_G = 0.00。原表の実値は −0.01 で、0.00 は同行の M_V）を使った場合: **+0.30**
- B9.5V–B8V 間で補間した場合: +0.31 / M_V で補間した場合: +0.29

**判定: ChatGPT の +0.30 は正しい**（原表値では +0.29、差 0.01 以内）。アンカーを +0.30 に変えると余裕は一律 0.40 小さくなるが、検証2のとおりラベルは変わらない。

### scan3 アンカー表の内部整合

- 現行 −0.1 は `dr4_beta_scan2.py` 由来で、scan3 の OLD アンカー表では (3.0, −0.1) 自体がアンカー点として入っている。
- しかし同表の隣接点 (2.2, +0.6) と (4.0, −1.0) から 3.0 を対数補間すると **−0.23** となり、表自身の値とも 0.13 等ずれる（内部不整合）。
- さらに旧アンカーは 2.2–5.5 M☉ の全域で EEM 2022 より **0.38–0.58 等明るい**（2.2: +0.60 vs +0.98 / 3.0: −0.10 vs +0.29 / 4.0: −1.00 vs −0.42 / 5.5: −1.70 vs −1.19）。−0.1 単独の問題ではなく、高質量側アンカー全体の系統差である。β走査の高質量側（M2 最大値の評価）にも効くため、別途記録して次回走査で扱うべき事項として残す。

### 推奨

- **正本は P&M EEM（2022.04.16）の +0.29（運用上 +0.30）に切り替え、現行 −0.1 は感度側に降格する。** 根拠: (1) 出典を辿れる一次資料であること、(2) scan3 の低質量アンカーも同じ EEM 系（Kurtenkov 2022 経由）であり表が統一されること、(3) 余裕が小さくなる保守側への変更であり、検証2のとおりラベルは変わらないこと。
- 閾値 1.5 等は、ChatGPT の言うとおり「物理的に確立された境界」ではなく暫定の運用基準と明記する（アンカー誤差 ±0.5 と追加余裕 1.0 の内訳のうち、後者の定量的裏付けは未整備）。
