# 集約画像 1 枚への点抽出の試行

DECaPS2 の集約画像 (バーデの窓、RA 270.70 / Dec -29.80、
r バンド、1024×1024、0.262"/px、約 20 arcmin²) に
素朴な点抽出 (ピーク検出 + 重心) を当てた実測。
コード: image_points.py / image_points_match.py。

## 結果

- 抽出点 **3,284 個** (164 個/arcmin²)。うち 98% が
  Gaia DR3 の実星と 1" 以内で一致 (偽検出は少ない)。
- 画像範囲内の Gaia 星は 6,013 個。等級別の回収率:
  G<18 で 97%、G18–19 で 72%、**G19–20 で 12%** と
  崖になる。これは画像が浅いのではなく、混雑場では
  背景の散らばり推定が未分解の星明かりに汚染され、
  閾値が上がるため。公式パイプラインの同時 PSF
  フィット (33 億天体のカタログ) との差がここに出る。
- **位置の床**: 抽出点と Gaia 位置のオフセットの
  散らばりは明るい星 (G<18、1,706 個) で
  **合計 約 66 mas** (軸あたり 40 / 53 mas)。
  Gaia BH1 の軌道の揺れ 約 2.7 mas の約 25 倍。
  2 エポックに分けても、各エポックの点はこの床を
  相手にする — 集約画像の点同士の差分では小さな
  揺れは拾えないことを、予想ではなく実測で確認。
- 中央値の系統オフセット (+15, −33 mas) には
  Gaia の元期 2016.0 と DECaPS2 の平均観測時期の差
  (固有運動分) も混ざっている。

## 結論

「1 枚に集点を当てる」こと自体は本物に動く (点の山は
作れる)。ただし残差の勝負は、この 1 枚を露出別に
分解し直したところから始まる — 公開された集約画像は
時間軸を平均化済みで、差分の材料は合成前の露出
カタログの側にある。位置の床 約 66 mas が、その
勝負の物差し。
