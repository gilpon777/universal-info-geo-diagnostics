## 2. Muse の考察で、良かった点

1. **a0 の位置づけの訂正。** TGE の a0 は、波長 541.4 nm の単色減光 A_0 の代表値で、A_G でも A_V でもない。「A_0 ベースの保守的な天井の代理量」と改め、k=0.8–1.1 の全範囲と a0_max の最悪ケースでラベルが不変であることを確認している。
2. **アンカーの出典の追跡。** 旧値 −0.1 の出典を辿れないことを見つけ、EEM 原表の補間値 +0.30 に切り替えた。余裕の閾値 1.5 等も、「物理的に確立された境界ではなく暫定的な運用基準」と明記している。
3. **ドライランの整理。** 現在の保留 4 件は、f の精度では解けない（#13 は光度天井、#8 は主系列前提、#10 は傾斜角、#12 は区間を半減しても M2 上限が 3 を下回らない）。**DR4 の精度向上だけでは決着せず、新しい種類のデータ（RVS エポック視線速度、進化星モデル）が要る**、という見立ては妥当（私の再計算でも、#12 の区間の対数幅を半分にすると M2 上限が約 17 になり、3 をまたぎ続ける）。
4. **フェイルセーフの徹底。** 欠損・不正値を「問題なし」側に倒さない設計（敵対ケース 13 件、has_orbit の型検査、JSON の標準化）。
5. **固定の位置づけ。** 固定を「通過点」とし、未検証項目を未検証のまま明記する方針（中谷さんの判断）。

## 3. 私の誤りの訂正と、方法の明記

1. **「星の消光が視線方向の総量を超えることは物理的にない」（v6・v7 の前提）は誤り。** a0 が代理量である以上、GSP-Phot の A_G が a0 を超えることは「物理的に矛盾」とまでは言えない（乖離の兆候にとどまる）。
2. **アンカー −0.1 を、出典を確かめずに使っていた。** 私が引用した M_G(3 M☉)=−0.1 は、Muse のスキャンのアンカー表の値で、v7・v8 の「主系列アンカー」という表現は根拠が不十分だった。
3. **GW の傾き「p=1.00±0.20」は、方法の記載が不足していた。** Muse の指摘のとおり、±0.20 は私のフィットの重み付けに依存する。出所を明記する:
   - **点集合の定義**: 強い点 = フィットの c>0 かつ S(g=4) が背景 p99 を超える点。計画窓 n=8、信号整合窓 n=11（重みなしだと (400, 1.0) の c が負になり n=10）。
   - **重み**: 私のコードは、設計行列と目的変数の両方に 1/max(S², 10⁻³) を掛けていた。最小二乗の目的関数では 1/S⁴ になり、**意図せず二重に効いていた**。この重みは「S² の誤差が S² に比例する」という仮定に相当するが、私は明記していなかった。
   - **重みを変えた再計算**（傾き ± 標準誤差、計画窓 / 信号整合窓）:

| フィットの目的関数 | 計画窓 | 信号整合窓 |
|---|---|---|
| 重みなし OLS | 0.86 ± 0.21 | 0.76 ± 0.23（n=10） |
| 重み 1/S²（S の加法的雑音の近似） | 0.92 ± 0.21 | 0.97 ± 0.36 |
| S 空間の非線形最小二乗 | 0.93 ± 0.21 | 0.88 ± 0.23（n=10） |
| 私の元の重み（1/S⁴） | 0.99 ± 0.20 | 1.02 ± 0.26 |

   - **結論**: いずれも 1 と矛盾しないが、「1.00±0.20」と方法名なしで書くのは過大だった。**osc_proj には誤差がない**（決定論的に計算している）ので、回帰は OLS が適切で、TLS（1.00〜1.71。重みで大きく変わる）は不適切。**「p ≈ 0.9 ± 0.2（OLS。重みで 0.76–1.02）」と方法名つきで併記する Muse の規約に賛成する。**
4. **cosθ の解釈。** 重みなしの fit では cosθ=+5.03 のような余弦として不可能な値が出る。S² の二次式をベクトルのノルムと見る解釈は成り立たず、**「経験的応答モデル」への格下げが妥当**。v8 §3 の「実効次元 D≈13–15」は、私の重みでたまたま |cosθ|≤0.54 に収まったことに依存しており、撤回する。
5. **三重系・GW フィットのコードについて。** Muse の検証記録にある `dr4_triple_search.py` と `gw_sfit_claude.py` は、中谷さんの中継でアップされたもので、私の本セッションの出力ではない。解数と係数の一致は、私の計算で確認できた（コードの本文そのものは未確認）。

## 4. 固定前に直したい点（提案）

### 4.1 統合規則 §5 の文言が、追記 8 と整合しない

統合規則 §5 は、「GSP-Phot の A_G が TGE の a0 を超える場合（**物理的に矛盾**）」と書く。しかし追記 8 第 1 部 §1 は、a0 を「A_0 ベースの代理量」とする。a0 が代理量なら、GSP-Phot が a0 を超えても物理的矛盾とは言えない。
- **改訂案**: 「GSP-Phot の A_G が、a0 の上限換算（k=1.1）を超える場合（代理量との乖離）」とする。
- **現 13 件への影響**: 該当するのは #12（GSP 2.67 に対し、1.1×a0=1.61）のみで、M1 範囲 [0.48, 0.95] もラベルも変わらない（他の天体は GSP が a0 を下回る）。
- 対応: 11/22 の固定を遅らせず、**固定後の追記 9** で直す案を勧める（文言の不整合は、判定ロジックに影響しない）。

### 4.2 光度天井の余裕の最も薄い点

新アンカー（+0.30）で、#4 の余裕は 2.33 等になった。閾値 1.5 等に対して 0.83 等の余裕しかなく、13 件で最も薄い。固定記録に「最も薄い余裕: #4（2.33 等）」と明記しておくと、DR4 で数値が動いたときの読み方が明確になる。

### 4.3 方法名つきの併記を、固定する文書に反映する

傾き p は OLS と TLS を方法名つきで併記する規約（Muse 提案 2）に、**重みの記載**（なし／1/S²／1/S⁴）と、**点集合の定義**（強い点の条件、n）を加えることを提案する。
