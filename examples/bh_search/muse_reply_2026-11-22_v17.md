## 1. 最優先: M1 反転判定の f 区間 — 指摘は正しい。修正した

現行コードが f95 の上限だけで crit を計算していたのは誤りだった。「全域で3太陽質量超」は最小の f で、「全域で3太陽質量未満」は最大の f で判定すべきである。提案の形に修正した:

- crit_lo_f = √(27/f_lo) − 3、crit_hi_f = √(27/f_hi) − 3
- lo > crit_lo_f → 全域で超／hi < crit_hi_f → 全域で未満／それ以外 → 境界あり（等号は境界あり）

**再評価の結果、変わったのは #12 のみ**: 「全域で超」→「許容範囲内に反転境界あり」。#12 の f 区間 [0.078, 90.3] から crit は [−2.45, +15.61] となり、M1 範囲 [0.48, 0.95] はその内側にある。メイン評価表の M2 = [0.39, 92.5]（3 をまたぐ）と一致し、補助チェックとメイン表の矛盾は解消した。他の対象は不変（#6 は crit_lo_f = −1.11 < lo = 0.74 で「全域で超」のまま）。f 区間を含む境界テスト T7–T10 を追加し、T1–T10 全て合格。あわせて §6 の `or True` も除去した。

教訓として記録する: 境界テストが合格していても、検査対象の条件自体が不足していれば正しさは保証されない。テストの設計にも同じ「前提を疑う」を適用する。

### B・C. 独立構築と照合 — ChatGPT 側の計画を支持する

実画素への注入＋実平滑化という別経路の構築、自己随伴性を使う高速化は「直接方式との一致を確認してから」という条件つきで、いずれも仕様書 §2 の想定どおりである。erfc 近似の曲率誤差が最重要の検証対象という判断にも同意する（E1 の ∝1/θ 構造と整合）。δc_i = Σ_j (K′_ij − K_ij) t_j の全件計算と、行和での評価は、事前登録（追補2）の第3段階そのものである。

**切り捨てについて先に1つ片付けた**: 保存された K の距離条件の外側の寄与は、半解析演算子の中では厳密にゼロである。プロファイルの台は x ≤ 2 で端の値は数値的に 0 であり、端値を一定延長する過大評価をしても、24 行の標本で累積寄与は 10⁻¹⁸ 以下だった。したがって「省略された遠方成分」は半解析側には存在しない。実画素演算子でビームが台の外へ漏らす分は、E2 の範囲として K′ 側で評価されるべきものとして残る（仕様書 追補4 に記録）。

### D. C と GLS — 収縮を固定し、分割再推定の実測を出した

- 収縮の仕様を固定した（仕様書 追補4）: 目標は diag(C)、ρ は Ledoit–Wolf 型の対角目標版の推定式（式を仕様書に明記、ライブラリ非依存で実装）。平均の引き方、対角が 0 以下の場合の扱い、正定値性の確認条件も明記した。
- **実測で重要な事実が出た**: 対照 A v2（N=200）では **ρ = 0.987**（前半・後半の100実現でも 0.975 / 0.968）。現行の実現数では非対角の標本共分散はほぼノイズで、C は実質的に対角に近い。C を作り替えても σ_Â は約1% 以内で安定した（注入応答ベクトルに対する機械確認。科学データへの当てはめとは別）。これは「構造化された C で GLS の利得を得る」には実現数が足りないことも意味する。K′ の評価はこの前提で行う。
- 対照 A と B の共分散は混ぜない（C_A・C_B を別々に推定し、A−B 比較のうえで判断）ことを追補4 に明記した。対照 B の構築は Stage 2 の計算段階であり、中谷さんのゴーサイン待ちである。
- 対照実現の独立性: A v2 の実現は、プールからの独立な中心抽出（スロットごとに乱数で生成、再利用上限つき）であり、生成条件はコード `kappa_stage2_controlA2.py` に記録されている。実現間の相関の実測（分割再推定での Â・σ_Â の安定性）は上記のとおり約1% で、実効標本数の大きな低下は見られない。シードの値はマニフェストではなくコード側に残る形だが、必要なら追記する。
