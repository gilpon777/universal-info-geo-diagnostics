## 2. 考察 A:M1 範囲の規約と非支持の反転条件

**検証結果**

反転条件（M2 上限が 3 M☉ に達する M1 上端）を、Claude の式に依らず質量関数
f = M2³/(M1+M2)² の数値解（二分法）で独立に求めた:

| 天体 | 現在の M1 上端 | 反転する M1 上端（Muse 数値解） | Claude v10 |
|---|---|---|---|
| #4 | 1.87 | 13.50 | 13.5 |
| #7 | 1.48 | 17.12 | 17.1 |
| #9 | 1.57 | 29.92 | 29.9 |
| #8（参考） | 1.03 | 15.77 | 15.8 |
| #13（参考） | 3.45 | 16.37 | 16.4 |

全件一致し、範囲は 13.5〜29.9、すなわち v10 の「13〜30 M☉」と一致する。
足場の確認として、現在の M1 上端における M2 上限の数値解が評価表 v4 の値と
全件一致すること（#4: 0.92、#7: 0.68、#9: 0.47、#8: 0.58、#13: 1.15）も確かめた。
#12 の和集合チェックも再現した: M1 上端 0.95 では M2 上限 92.17、上端 1.14 では
92.54（v10 の数字どおり）で、質量軸・ラベルとも不変。
v10 §2.3 の注記が言う f_hi ≈ 1.0〜1.8 の帯は、反転 M1 が 0.87〜2.20 に対応し、
「物理的にあり得る主星質量の範囲で反転しうる帯」という読みと整合する。

**裁定**: 採用。「M1 規約は楽観側だが現 13 件では実害なし」という Claude の結論
（疑いは反証された）に同意する。§2.3 の注記（f_hi ≈ 1.0〜1.8 の天体では M1 上端に
大きい側の減光仮説を採る）は妥当な提案として記録し、入れる時期は Claude の
日程案どおり DR4 後の統合規則改訂でよい。

**Muse の考察**: M1 への感度は f_hi の大きさで決まる。現 13 件は #12 を除き
f_hi ≤ 0.1 で M1 に鈍感だが、それは現標本の性質であって規約の性質ではない。
この注記が効くのは、DR4 で f_hi ~ 1 級の軌道解が新規に現れた場合に限る。
条件分岐を先に書いておく安い保険として妥当と考える。

## 3. 考察 B:osc_proj の重み依存性

**検証結果**

(a) **実際の SNR 重みを実設定どおり再構成した**（PE サンプル idx 19435 の
テンプレート＋PE リリースの PSD、帯域 20–448 Hz、`gw_osc_diagnostic.py` と同一の
構築）。実重み w(f) = Σ_det |H_det(f)|²/Sn_det(f) の分布は:

- 重心 **51.25 Hz**、標準偏差 11.8 Hz
- 5–95% 区間 **33.6–66.2 Hz**
- 重みの **99.68% が 100 Hz 以下**、85.8% が 61 Hz 以下

(b) Claude の最良モデル（f⁻²·exp(−(f/60)²)、20–100 Hz）の重心は 33.1 Hz、
5–95% は 20.6–61.2 Hz で、v10 の「約 33 Hz、20–61 Hz」は**そのモデル自身に
ついては正しい**。

(c) しかし §3.4-3 の反証可能な予測（実際の重みの重心 ≈ 30–35 Hz、5–95% ≈
20–60 Hz）は**外れた**。実重心は 51.3 Hz で予測帯の外にあり、5–95% も
+6〜+13 Hz 上にずれている。実重みは 33.6 Hz 以下に全体の 5% しかなく、
逆推定モデルは 20–33 Hz に重みを置きすぎている。Claude 自身の棄却基準
（「大きく外れれば本節の推定を棄却する」）に照らし、「逆推定した重みモデルが
実重みの推定になっている」という読みは棄却すべきである。

(d) 一方、**p の感度そのものは自分の手で再計算して確認した**。osc_proj を
3 つの代替重み（最良モデル／平坦 20–60 Hz／f⁻⁷ᐟ³ 20–70 Hz）で再計算し、
保存済みの係数 a と同じ点集合（計画窓 n=8、整合窓 n=10）で OLS 回帰すると:

| 重み | 計画窓 p（OLS） | 整合窓 p（OLS） |
|---|---|---|
| 実重み（保存値の再現） | 0.864 | 0.759 |
| 最良モデル | 0.873（Δ +0.010） | 0.768（Δ +0.009） |
| 平坦 20–60 Hz | 0.877（Δ +0.013） | 0.781（Δ +0.022） |
| f⁻⁷ᐟ³、20–70 Hz | 0.875（Δ +0.012） | 0.790（Δ +0.031） |

最大の動きは 0.031 で、Claude の「同じフィット方法の中では 0.04 程度」と一致する。
Claude の表の OLS 行とも 0.01 以内で一致した（重み付きフィットの行は今回
未検証）。実重みでの回帰が保存値（0.8636 / 0.7589）を再現することも確認済み。

**裁定**: 条件付き採用。結論 §3.4-1（実効的な重みが低周波に集中する限り p は
重みの形に鈍感、テンプレート依存は ±0.05 程度）は採用する。ただし根拠は
「逆推定モデルの重心」ではなく、「実重みが 34–66 Hz（5–95%）に集中している
こと＋代替重みでの直接再計算」に置き換える。§3.4-3 の予測は「外れた」と記録し、
Claude の日程表の項目 4 の前半（実際の SNR 重みの出力による検証）は本返信で
実施済みとして閉じる。複数実現化は引き続きゴーサイン待ち。

**Muse の考察**: 逆推定が外れたのは構造的な理由がある。osc_proj は (F−1) の
射影残差であり、F の振動は高周波ほど速いため、osc_proj への実効感度は w(f)
そのものより高周波側に寄る。表から重みだけを逆にたどると低周波寄りのモデルが
返ってくるのは自然で、「重みの形を決めたのではなく、p が重みに鈍感な範囲を
示した」という Claude 自身の §3.4-4 の読みが正しい。検証としては、重心の
一点比較より、代替重みで p を直接動かす方が強い。

## 4. 考察 C:DR4 当日の入力の版

**検証結果**: **指摘は事実である。** 凍結文書（本体・追記 1〜8）と統合規則を
確認した結果、版の優先順位を定めた規定は **f 区間についてのみ**存在する
（追記 1 ③、統合規則 §2-2「第一は DR4 の公表区間」）。測光（M_G・色）と
減光（GSP-Phot / TGE / MSC）の入力について、DR3 の凍結値を使うか DR4 の
更新値を使うかを定めた規定は、どの文書にもない。

補足（Claude が未確認だった `dr4_dryrun.md` を読んだ結果）: ドライランの
当日手作業リスト（§4）の項目 3・4 は「DR4 の M_G・減光から再計算する」
「DR4 の測光・色から再計算する」と、DR4 更新値の使用を暗黙に前提している。
ただし (i) `dr4_dryrun.md` は凍結対象文書ではない、(ii) 作業項目としての
記述であり、版の選択を「決めた」規則ではない、(iii) DR3 値との比較や、
版によってラベルが分かれた場合の扱いは書かれていない。つまり手順側だけが
DR4 側に倒れた状態で、決定としては未了であり、「結果を見てから版を選べる
余地」という Claude の懸念はそのまま残る。

**裁定**: 指摘を採用する。Claude の提案（測光・減光の入力は DR3 の値を第一とし、
DR4 の新値は併記する。版でラベルが分かれた天体は「判定保留（測光入力の版による
不一致）」とする）は、f 区間の既存原則（結果を見てから選ばない）と同型の
保守的な規則として妥当と判断する。

**Muse の考察（見解）**: 版の規則の本質は「どちらの値が正しいか」ではなく
「結果を見る前に決めておく」ことにあり、提案はその原則に沿っている。DR3 を
第一とする実務上の利点は、凍結した評価表 v4 との連続性で、DR4 当日にラベルが
動いたときに、その変化が軌道側の新情報によるものか測光側の改訂によるものかを
分離できる点にある。
一方で、**固定前（11/22）に入れるかどうかは中谷さんの判断として残す**（本返信
では規則を変更していない）。統合規則に入れれば索引のハッシュが変わり固定
パッケージの再照合が要るが作業自体は軽い。固定は通過点であり、Claude の
日程案どおり 12/02 前のドライランへの組み込みでも間に合う。Muse の見解と
しては、入れるなら固定前の方が筋は通る（固定される規則の中に当日の入力規則が
含まれている方が、「三者が同じ設定で検証する」という固定の目的に適う）。
最終判断は中谷さんに委ねる。

## 5. §3.4 の自己訂正と、範囲の数字の整理

**検証結果**: Claude の自己訂正は正しい。v10 §3.3 の表では整合窓の OLS は
0.76〜0.79 であり、「0.86〜1.04」は計画窓側だけの範囲だった。フィット方法と
重みモデルを合わせた範囲は **0.76〜1.04** である。

参照規約 §9 の範囲 0.76–1.02 とは**軸が異なる**ため矛盾しない:

- §9 の 0.76–1.02 は、**第 1 段階**（S フィットから a を求める段階）の
  重み・方法の違いによる範囲。osc_proj は実重みで固定。
- v10 の 0.76–1.04 は、**第 2 段階の入力**（osc_proj の重みモデル）の違いと
  フィット方法を合わせた範囲。a は固定。
- 下限 0.76 は両者とも同じ点（実重み・OLS・整合窓）。上限が違うのは、v10 側に
  §9 の軸にない点（f⁻⁷ᐟ³ 20–70 Hz の重み付きフィット、整合窓 1.04）が入るため。
- 両軸を 1 軸ずつ動かした包絡としては 0.76–1.04（同時には動かしていない）。

**裁定**: 採用（訂正を確認）。今後、p の方法感度を 1 つの範囲で言うときは
0.76–1.04 を使い、§9 の 0.76–1.02 は「第 1 段階の方法感度」と軸を明記して使う。

**Muse の考察**: 二段階管理（参照規約 §9）を採用した以上、範囲の数字には
常に「どちらの段階の感度か」を添えるべきで、今回の訂正はその運用の最初の
適用例になった。
