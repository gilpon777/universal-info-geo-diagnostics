## 1. 参照規約

### 1.1 入力

- 点: Stage B 格子16点（`wf_data/gw231123_inject_recover.json`）＋予測検証の追加3点（`gw_prediction_check.json`）＝ 19点 × 2窓。
- 窓: 計画窓 `plan_[-1.5,+0.5]`、信号整合窓 `matched_[-0.6,+0.3]`。
- g 格子（全点共通）: 0.1, 0.25, 0.5, 1, 2, 4。各点の S 系列そのものは `gw_sfit_coefficients.json` に格納。
- osc_proj: `gw_osc_diagnostic.json` の実設定値（帯域 20–448 Hz、SNR 重み）。

### 1.2 フィット

- **対象**: S(g)² − S0²。
- **S0**: 無注入の実測ベースライン。窓ごとに固定する（S0 自由にはしない）。
  - 計画窓 S0 = 0.061238571446013
  - 信号整合窓 S0 = 0.109410514386627
- **モデル**: b·g + q·g²（切片なし）。
- **推定**: 通常最小二乗（OLS、`numpy.linalg.lstsq`）。
- 背景 p99（有意点の定義に使用）: 計画窓 0.095338701947678、信号整合窓 0.139578622601240。

### 1.3 係数からの量の定義

- **a = √q**。q > 0 の点でのみ定義する。**q ≤ 0 の点では a は定義不能**とし、欠測扱いにせず係数表にその旨を明記する（§3）。
- **cosθ 相当量 = b / (2·a·S0)**。a が定義できる点でのみ定義する。これは2次係数の代数的な読み替え量であり、**真の余弦ではない**（|値| > 1 を取り得る。実例は §2 の表と §6.1）。名称に「相当量」を必須とする。
- **残差 RMS**: rms_S はモデル S = sqrt(max(S0²+b·g+q·g², 0)) と実測 S の差の RMS。rms_S2 は S² 空間での残差の RMS（フィットが実際に最小化した量）。両方を併記する。

### 1.4 傾き p の規約

- p とは **log a vs log osc_proj の回帰傾き**を指す。
- 点集合: **有意点**（S(g=4) が背景 p99 を超える点）のうち、**a が定義できる点**。計画窓 8 点、信号整合窓 10 点（信号整合窓の有意点は11点だが、(400, 1.0) は q ≤ 0 で a が定義できないため落ちる）。
- **報告の規約**: OLS 傾きと TLS（直交回帰・主軸回帰）傾きの**両方を方法名つきで併記**する。どちらか一方を方法名なしに「p」と呼ばない。両者は同じ係数から出る別の統計量であり、どちらが正しいという関係にはない。
- **主解析と補助比較の位置づけ（§9 で確定、第11回で本項にも明記）**: 併記のうえで、**主解析は OLS** とし、**TLS は補助的な比較値**とする。TLS は数学的に誤りなのではないが、両軸の誤差比という誤差モデルが未定義のため主解析には採用しない。引用の中心値は OLS で書く（引用の形は §9 項目1）。
- 保存された**実測 g99 の log–log 回帰**（v7 型）は係数表とは別の参考量であり、p の定義には使わない（§4.3）。

## 6. 確定したこと／確定していないこと

### 6.1 確定したこと

1. **負の q の実在**: §3 の6件。特に信号整合窓 (400, 1.0) の q = −3.174×10⁻⁴ は ChatGPT の値（−3.17×10⁻⁴）と3桁一致し、符号はフィット方法に依らない。真のノルムの2乗係数なら q ≥ 0 のはずであり、2次式は恒等式ではなく局所的な経験フィットであることの直接の証拠。
2. **p の方法依存性**: 同一の係数表から、OLS では 0.864/0.759、TLS では 0.999/1.007 が出る（§5）。「p = 1.00 ± 0.20」のような方法名なしの確定値としては扱わない。今後の報告は §1.4 の規約（両方法を方法名つきで併記）に従う。
3. **実測 g99 回帰と osc_proj の物差しの維持**: 保存された実測 g99 の回帰は Claude v7 の傾き（−0.91/−1.07）を再現する（§4.3）。係数の解釈論とは独立に、osc_proj を感度の物差しとして使う実測側の関係は維持される。
4. **ベクトル解釈の格下げ（済み）**: cosθ 相当量は真の余弦ではない。係数表の中に |cosθ 相当量| > 1 の点が実在する（計画窓 (400, 1.0) +5.03、信号整合窓 (2000, 0.5) +3.57、(2000, 0.3) +1.29）。S は正規化相関の最大絶対値でありベクトルのノルムではなく、19点は同一ノイズ実現を共有する。したがって S² の2次式は**経験的な応答モデル**として保持し、cosθ をベクトル間角度として扱う解釈と、独立性を前提とする実効次元 D・確率の推論は格下げ済みとする（根拠の詳細は `gw_sfit_reproduction.md` §4）。

### 6.2 確定していないこと

1. **Claude の cosθ 要約統計の出所**: 計画窓 平均 −0.19・標準偏差 0.26・n=16、信号整合窓 −0.08・0.28・n=17、最大 0.54 は、M1–M4 のどの方法・どの自然な点集合でも再現しなかった。**Claude のフィット／回帰コードと全点係数の公開待ち**。
2. **Claude の ±0.20 の出所**: 数値としては OLS 傾きの標準誤差（計画窓 0.205）と一致するが、TLS のジャックナイフ誤差は ≈0.59/0.82 であり、±0.20 にはならない。どちらの方法の誤差なのかは未同定（同上、コード公開待ち）。
3. **Claude が実際に使った回帰方法**: TLS が点推定（1.00/1.02）を再現する唯一の候補だが、これは同定ではなく消去法による候補であり、確定ではない（同上）。
4. **窓間 a 比**: Claude の 1.59 ± 0.10（中央値 1.53）に対し、本表（M1）では平均 1.41・中央値 1.37 で届かなかった。係数公開後に再照合する。
5. 多実現化による cosθ 分布・D の検証は原理的に可能だが、新しい実行段階であり本パッケージの範囲外。

## 7. 使い方

- 今後この Stage B の係数や傾きに言及するときは、本書の規約（§1）と係数表（§2、`gw_sfit_coefficients.json`）を引く。
- 傾きを引用するときは「OLS 0.86/0.76」「TLS 1.00/1.01」のように方法名を必ず添える。
- 位置づけは **OLS を主解析、TLS を補助比較** とする（§9）。引用の中心値は OLS で書き、TLS は比較値として併記する。TLS の数値は記録として残すが、主結果として単独で引用しない。
- 方法比較（M2–M4）や解釈の検討が必要な場合は `gw_sfit_reproduction.md` を併せて引く。

## 8. 追補（2026-11-20、Claude v9 と Muse の再計算）

§6.2 の未確定事項は、Claude のコード到着（2026-11-19）と v9 の方法明記で解消した。

1. **±0.20 の出所（解消）**: Claude の重み付き（CL）フィットの OLS 標準誤差だった。CL 法は曲線フィット (S²−S0²) = b·g + q·g² の各行に 1/max(S², 1e-3) を掛けており、目的関数では実効重み 1/S⁴ になる。Claude v9 はこれを「意図せず二重に効いていた」と明記した。
2. **重みを変えた傾き（全行を Muse が独立に再現した）**: 曲線フィットの重みを変え、強い点（q > 0 かつ S(g=4) が背景 p99 超過。n は方法で変わる）について log a vs log osc_proj の OLS 傾きを取ると:

| 曲線フィットの目的関数 | 計画窓 | 信号整合窓 |
|---|---|---|
| 重みなし OLS | 0.86 ± 0.21（n=8） | 0.76 ± 0.23（n=10） |
| 重み 1/S²（行に 1/S を掛ける） | 0.92 ± 0.21（n=8） | 0.97 ± 0.36（n=11） |
| S 空間の非線形最小二乗 | 0.93 ± 0.21（n=8） | 0.88 ± 0.23（n=10） |
| 元の重み（実効 1/S⁴） | 0.99 ± 0.20（n=8） | 1.02 ± 0.26（n=11） |
